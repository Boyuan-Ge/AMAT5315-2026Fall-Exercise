# Week 3 Ising Monte Carlo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, validate, publish, and freshly reproduce the complete Week 3 two-dimensional Ising Monte Carlo assignment in `week3/`.

**Architecture:** A Rust crate separates lattice physics, Metropolis and Wolff updates, run protocols, streaming artifact I/O, statistical analysis, plotting, and CLI dispatch. Large JSON Lines datasets are written and read sequentially, while deterministic seeded generators make every contract run byte-reproducible.

**Tech Stack:** Rust 2024 edition, Cargo, `rand 0.9`, `clap 4`, `serde`, `serde_json`, `anyhow`, `rustfft`, `plotters`, Make, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-09-10-week3-ising-design.md`

## Global Constraints

- Work in the existing `AMAT5315-2026Fall-Exercise` repository and put all new assignment code under `week3/`.
- Use the two-dimensional square-lattice Ising model with `J = 1`, no field, periodic boundaries, and temperature in units where `k_B = 1`.
- Random-site Metropolis defines one sweep as exactly `L^2` proposals.
- Wolff defines one sweep as enough complete cluster flips to touch at least `L^2` spins.
- Every stochastic command uses a user-visible seed and an explicitly seeded `StdRng` from `rand = "0.9"`.
- The Metropolis contract run uses sizes `[32, 64]`, seeds `1042` and `42`, 27 temperatures, 2000 equilibration sweeps, 5000 ordinary measurement sweeps, and 100000 measurement sweeps from `T=2.0` through `T=2.6`.
- The Wolff contract run uses sizes `[32, 64]`, 13 temperatures from `T=2.0` through `T=2.6`, 2000 equilibration sweeps, and 100000 measurement sweeps.
- `series.jsonl` fields are exactly `L`, `T`, `sweep`, `M`, and `E`; `M` and `E` are written to six decimal places.
- `run.json` fields are exactly `sizes`, `t_grid`, `eq_sweeps`, `meas_sweeps`, `meas_sweeps_critical`, `sample_every`, `seed`, and `algorithm`.
- `week3/artifacts/` and `week3/artifacts-wolff/` stay out of Git; `docs/week3/spins.jsonl` is tracked.
- Use test-driven development: write one behavior test, observe its expected failure, write the minimum implementation, and rerun all relevant tests before refactoring.
- Do not implement optional extensions or the neural-sampler challenge.
