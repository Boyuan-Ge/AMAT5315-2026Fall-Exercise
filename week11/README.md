# Week 11 — Hard problems, reductions, and tensor-network sampling

The Rust tool [tnsample](src/main.rs) plans and contracts binary tensor networks and samples from one stored contraction. The exercise uses `pred 0.6.0`, `omeco 0.2.6`, and seed **2026**. Full runs and plots stay outside Git.

## Reproduce

On Ubuntu/WSL with Rust and Python available, install the build dependencies and run from this directory:

```sh
sudo apt install cmake libclang-dev
cargo install problemreductions-cli@0.6.0 --locked
python3 -m venv .venv
.venv/bin/pip install matplotlib==3.11.2
bash scripts/run.sh
.venv/bin/python scripts/plots.py
```

Measured environment: Ubuntu WSL2 x86-64; Rust 1.98.1; CMake 4.2.3; Python 3.14.4; Matplotlib 3.11.2. The [CLI specification](tnsample.design.toml) describes the mode settings. The planner uses eight Rayon threads and omeco's own seed policy; greedy tie breaking may vary. The seed passed to the CLI controls the Rust lattice and sample RNG. The Rust weight calculation uses log-sum-exp to avoid overflow in Boltzmann weights; ground-state energy and count are tracked separately by min-plus with tie counts.

## Factoring round trip

`pred path` finds **Factoring → CircuitSAT → SpinGlass**. The solver treats the target as an energy minimization problem, then maps the spins back. With little-endian bits for each factor, the decoded results are:

| Target | Decoded result | Evaluation |
|---:|---|---|
| 6 | 2 × 3 | Min(0) |
| 7 | 3 × 2 | Min(1), not a factorization |
| 15 | 3 × 5 | Min(0) |

The nonzero evaluation for 7 is the negative control: every two-bit input pair fails to produce 7. The restricted minimum gate energy is not a guarantee of satisfying the original problem. A recovered panic warning from `pred solve` 0.6.0 can appear before its successful ILP output.

P problems have polynomial-time solvers; NP decision problems have polynomial-time checkable yes witnesses. The general spin-glass decision problem is NP-complete, but this reduction does not establish that factoring is NP-complete. Translating the instance and reading back a solution are separate from the expensive search.

## Logic gates

![Every gate truth-table row and all 16 circuit states](https://github.com/Boyuan-Ge/AMAT5315-2026Fall-Exercise/releases/download/week11-results/gates.png)

With `s=2x-1`, the AND and OR floors are −3; NOT, COPY, SET0 and SET1 have floor −1; XOR has floor −4 after minimizing over its helper. For AND(1,1,1), all spins are +1, giving `1−2−2−1−1+2=−3`. All rejected rows are at least two energy units above the corresponding floor. Sharing the AND output with NOT and pinning the circuit output to 1 gives exactly three states at energy −5, for inputs 00, 01 and 10. A multiplier cell combines these rules so that `p*q+a+b=z+2*c`; pinning the output turns the circuit into a search over factor bits.

## Exact spin contraction and sampling

![Greedy versus TreeSA contraction width and the sampled energy histogram for factoring 15](https://github.com/Boyuan-Ge/AMAT5315-2026Fall-Exercise/releases/download/week11-results/factoring.png)

The open 10×10 ferromagnet has 180 bonds: the solver gives **Emin = −180**, **g₀ = 2**. Open lattices use `−Σ Jij si sj`; bundles use the `pred` convention `+Σ Jij si sj + Σ hi si`.

For the 104-spin factor-15 bundle at β=2, **Emin = −299**, **g₀ = 1**, **log Z = 598.3179452170**, and **sc = 5**. The probability of drawing a ground state is `g₀ exp(−β Emin − log Z)`. Each sample is generated by walking the stored tree downwards and choosing compatible child entries proportional to the product of their stored weights. No rejection or fresh contraction is needed. The plotting audit recomputes all 2,000 energies directly and calls `pred extract` on a sampled ground state; it decodes to **3 × 5**.

For k=2…8 the study plans, but does not contract, the larger factor bundles. The exact cost estimates are in the local run manifests. TreeSA finds the nearly linear separator-width trend, about `2k+1` for k≥3: since sc is a base-two logarithm, this still means exponential space in k. The dashed 8 GiB line accounts only for one float64 value per entry, not all runtime memory.

## N-queens

![Exact board counts for sizes 4–10 and six-queen sampling frequencies](https://github.com/Boyuan-Ge/AMAT5315-2026Fall-Exercise/releases/download/week11-results/nqueens.png)

The network uses three-index carry tensors with nonzero rows 000, 011 and 101. Carries start at zero; rows and columns end at one; diagonals have free ends. Contracting only compatible nonzero entries gives **2, 10, 4, 40, 92, 352, 724** boards for N=4…10. Each board has one valid assignment of carries, so the sampling distribution is uniform over boards. The audit independently verifies columns and both diagonals for all **400 boards** (200 each for N=6 and N=8).

For the live demonstration, show the three figures, explain the factor-15 sample and why TreeSA reduces width without making it polynomial, then show a sampled 8-queen board. The experiment outputs and sampled board example are summarized by `artifacts/summary.json`.

### Measured results

- Factor 15: **1,490** ground states in 2,000 independent draws, against **1,455.29** expected (binomial standard deviation about 20); the difference is about 1.75 standard deviations.
- For k=2…8, measured greedy sc: **5, 11, 17, 20, 33, 38, 52**; TreeSA sc: **4, 7, 9, 11, 13, 15, 17**.
- Six-queen sample frequencies (lexicographically sorted boards): **48, 44, 55, 53**; eight-queen distinct boards: **81 of 92** from 200 draws, versus about 82 expected.
- One sampled eight-queen board, written as zero-based column by row: `[5, 1, 6, 0, 2, 4, 7, 3]`.
